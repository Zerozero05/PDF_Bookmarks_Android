# PDF 书签目录工具 Android v0.1.9 使用说明

v0.1.9 已由用户确认验收并转为正式版。发行状态调整不改变原 APK、版本号、签名及程序功能。本说明对应仓库当前 v0.1.9 程序；用户总体验收不等于所有设备、提供者和故障演练均已验证，详细证据见[验证记录](../VALIDATION.md)。

## 适用任务与准备

本工具将一本 PDF 和一份已准备的目录 JSON 合成为带完整多级书签的 PDF。它还可为已识别的享做笔记资源同步享做自己的目录，无需开启无障碍服务。文件处理在本地完成，应用不请求联网或全盘访问权限。

准备 PDF 与目录 JSON，二者不必同名或放在同一文件夹。JSON 可来自 PC 版目录工具或 Jasminum，格式见下方[目录 JSON 与页码映射](#目录-json-与页码映射)。当前不提供 OCR、自动文字提取、目录编辑工作台或批量处理。

已验收设备为 HUAWEI MatePad Pro 12.2（MRO-W00、HarmonyOS 4.2.0、12 GB RAM、256 GB 存储、2800×1840）。应用最低要求支持 APK 的 Android 8.0／API 26 环境；HarmonyOS NEXT 不属于本版主路线。

## 安装、升级与华为文件授权

1. 从[发行页面](https://github.com/Zerozero05/PDF_Bookmarks_Android/releases/tag/v0.1.9)下载 `PDF_Bookmarks_v0.1.9_android.apk`，或通过数据线传到平板。可用同页面的 `SHA256SUMS.txt` 核对下载文件。
2. 在平板文件管理器中打开 APK。若系统询问是否允许该来源安装应用，进入对应设置允许后继续；具体页面名称以当前系统显示为准。
3. 从旧版本升级时选择覆盖安装，保留应用数据。不要先卸载或清除数据：应用内原件备份、恢复记录及文件授权依赖这些数据。正式发行 APK 沿用原升级签名；不要使用 GitHub Actions 的临时构建包覆盖安装。
4. 打开应用“PDF目录工具”。它无需无障碍、全盘访问或联网授权；访问文件时由系统选择器授予所选文件或文件夹权限。
5. 首次粘贴享做路径或执行同路径替换，点击“授权路径所在文件夹”，在系统文件选择器中找到实际文件所在目录或其父目录，选择该文件夹并按系统提示允许读写。例如授权共享内部存储下的“享做笔记/note”后，可解析其中其他笔记资源路径。
6. 授权完成后返回应用，点击“使用此路径”或重新读取。选择错误目录可取消，原来选定的文件保留；程序不会反复自动打开选择器。

**路径不是权限。** 单个 PDF 的写权限不能代替原文件夹的创建、改名权限。文件来源必须支持创建暂存文件及改名，才能同路径替换；不支持时使用另存副本。提供者支持时，应用持久保存授权；授权失效时重新授权对应目录即可。

## 第1节：选择文件、粘贴路径与取消

可分别点击“选择 PDF”“选择目录 JSON”，从系统文件选择器选择文件；也可分别点击“粘贴 PDF 路径”“粘贴 JSON 路径”，输入后点“使用此路径”。

要更新享做已有笔记，在享做笔记详情中复制 **PDF 路径**。应选择该笔记资源目录里的原 PDF，格式例如：

```text
/享做笔记/note/note_<笔记ID>__res__/.note_<笔记ID>.pdf
```

这只是路径格式，实际使用应粘贴自己的完整笔记路径。不要选择 `.ncc` 笔记文件、资源文件夹本身，或内部存储根目录的“带目录”副本：处理副本不会更新原笔记。

支持共享存储中的 `/享做笔记/...`、`/storage/emulated/0/...`、`/sdcard/...`、`file://` 和已有访问授权的 `content://`。电脑显示的“此电脑\HUAWEI MatePad Pro\内部存储\…”是 Windows 的设备位置，不是 APK 可直接读取的路径；请改用平板详情中的路径或系统选择器。不能用 Windows 盘符或 `/data`、`Android/data`、`Android/obb` 绕过其他应用私有存储限制。

误触或选错时：

- 路径输入：点击“取消路径输入 / 返回”，或按系统返回。
- 系统文件选择器／授权选择器：按系统返回取消，原选择保留。
- 文件读取：点击顶部“取消读取 / 返回”，或按系统返回，可重新选择并读取。

读取取消不会改动原 PDF 或 JSON。实际保存、改名切换及恢复过程中，应等待核验结果，不以强杀进程作为返回方式。

## 第2节：核对目录与目标页

1. 点击“读取文件并预览目录”。程序显示所选 PDF 的实际总页数、导入目录数及已有书签数。
2. 目录以“目录标题”和“目标页”两栏显示：标题保留层级缩进，可换行；目标页是从1开始的 PDF 实际页码。目录区域可独立上下滚动，表头固定。
3. 点击整行的标题或页码，查看对应页面；宽屏下页面预览在目录旁边。逐项核对标题、层级和实际落页，避免将印刷页码当成 PDF 实际页码。
4. 如果 PDF 已有书签，默认跳过生成，不会合并旧书签。确需更新时，勾选“替换PDF已有的整棵目录（有旧目录时才需要）”，重新核对后再勾选“我已核对目录标题、层级和实际跳转页”。修改替换选择会清除之前的核对勾选。

勾选核对不会放宽权限、格式或页映射检查。换输入文件会使旧预览和已生成结果失效；记住上次选定文件不等于已经重新加载目录，需要重新点击读取。

如果所有目标页有同一偏移，调整 JSON 中的 `mapping.offset`；插页／缺页用分段映射，见[页码格式](#目录-json-与页码映射)。本版没有在预览中编辑页码或层级的工作台。

## 第3节：生成与保存

常用区域显示当前处理设置、“生成…”按钮，成功保存后显示“打开已保存的 PDF”；存在成功关联旧件或未完成清理时才显示唯一清理入口。“处理选项”和“更多操作与恢复”可展开，收起不改变功能。

### 默认选项

| 选项 | 默认值 | 作用 |
| --- | --- | --- |
| 直接替换原 PDF（原路径与名称） | 开启 | 替换第1节选定的原 PDF，保持其所在路径与文件名 |
| 替换后同步享做目录 | 开启 | 仅在替换已识别的享做资源 PDF 时同步目录；普通 PDF 不猜测所属笔记 |
| 享做目录处理方式 | 保留已有目录并添加新目录 | 保留手动项和旧项，添加缺少的新项 |
| PDF及所选同步成功后，删除所选 JSON | 关闭 | 满足成功与删除校验条件后，删除这一份来源 JSON |

换输入文件后，JSON 删除恢复关闭、享做目录模式恢复保留并添加。重新创建界面也恢复保留目录模式，避免沿用上次全部替换选择。

### 同路径、同名替换

1. 核对原 PDF 路径。如果要更新享做，先保存笔记，在系统设置中 **强行停止享做，不要清除数据**，让它保持关闭。
2. 保持“直接替换原 PDF”勾选，按需选择享做目录模式和 JSON 删除选项。
3. 点击“生成并替换原 PDF（同路径、同名）”，核对确认弹窗中的条目数、目标文件、同步模式及删除范围，再确认执行。
4. 等待程序报告原路径同名替换并核验成功，再打开输出文件；对享做原笔记，重新打开并核对目录、跳转和原笔迹。

程序先在本地副本生成，检查书签、页数及原字节前缀；替换前将原 PDF 保存到应用内 `files/pdf-backups/`，在原文件夹写入并重新读取新暂存 PDF。新件核验成功后，将原件改为唯一备份名，再把新件改为原名，逐阶段保存恢复记录、实际 URI 和内容校验结果。成功后默认保留同目录旧 PDF 与应用内 PDF 备份；只有后续明确清理才删除。

程序不会打开原 PDF 的截断写入流，也不会先删除原文件再生成新文件。两次改名之间可能暂时没有原文件名，该过程是可恢复的改名流程，不等于系统原子替换。文件来源不支持创建／改名，或文件预览后被改变时停止；请依据提示处理，不能靠重复点击绕过检查。

### 另存副本

取消“直接替换原 PDF”，点击“生成带目录副本（待另存）”。生成成功后程序展开“更多操作与恢复”，点击其中的“另存已生成的 PDF…”才会打开系统选择器，再选择输出位置；生成本身不会自动弹出保存选择器。建议名称为 `<原文件名>_带目录.pdf`，可以自行调整；原 PDF 保留，输出不能选为 PDF／JSON 输入文件本身。

另存模式不直接同步享做原笔记目录；需要时将保存的新 PDF 导入享做。保存失败时，原文件和已生成副本保留，可在“更多操作与恢复”使用“另存已生成的 PDF…”选择另一位置。已生成结果仍有效时，不必重新生成。

### PDF 书签与享做目录是两个独立选择

- 第2节“替换PDF已有的整棵目录”：控制 PDF 内部书签。默认遇到旧书签时跳过；明确替换时覆盖整棵旧书签树，不合并。
- 第3节“享做目录处理方式”：控制享做自己的 `catalog.json` 目录树。享做可能使用它而不重新读取 PDF 内部书签，所以仅替换 PDF 不一定更新享做界面目录。

| 享做模式 | 成功后的目录 | 旧目录副本 |
| --- | --- | --- |
| 保留已有目录并添加新目录（默认） | 保留已有手动与导入目录，按标题和页标识添加缺少的项；重复同步不重复追加同一项 | 保留本次同目录及应用内目录备份，确认正常后可统一清理 |
| 用新目录替换全部已有目录 | 最终只采用本次 JSON 的标题、层级和目标，全部旧项（包括手动目录）被替换 | 新目录核验成功后自动删除本次外部旧目录及内部目录恢复副本，不能再用它们恢复 |

保留模式下，同名但不同目标页的手动项会与新项并存，无法唯一匹配时停止。全部替换期间仍先使用必要事务副本，写入或清理失败时保留恢复材料；它不先删活动目录再写新目录。清理前显示本次两份目录副本的完整路径，按已经选定的全部替换模式自动删除，不追加第二次确认。**此操作只删除本次两份旧目录副本，PDF 备份不自动删除。**

完全相同的目录树无需重写，不产生本次目录备份，也不删除以前任务的目录备份。两模式均保留目录根字段，不修改笔迹、页面配置或其他笔记。详细格式与页面映射边界见[享做目录同步](ENJOY_DIRECTORY.md)。

### 可选删除来源 JSON

展开“处理选项”，勾选“PDF及所选同步成功后，删除所选 JSON”。只有保存结果核验成功、所选享做同步和相关清理已完成、来源仍是同一份未变化 JSON 且具有删除权限时才执行；否则 JSON 保留并显示原因。

这一选项与统一旧备份清理独立：统一清理不删除来源 JSON。仅同步目录操作不替换 PDF，也不删除 JSON，即使此前勾选了删除 JSON，该独立入口仍保留 JSON。输入切换后删除选项恢复关闭，避免误删下一本书的文件。

### 仅同步当前 PDF 目录到享做

如果当前享做资源 PDF 已含本次 JSON 对应的书签，可在“更多操作与恢复”点击“仅同步当前PDF目录到享做”。须先读取、核对并勾选核对，当前 PDF 与 JSON 的标题、层级和 PDF 实际页逐条一致。

保存笔记并强行停止享做后，在确认弹窗继续。此操作使用同一组享做目录模式：可保留并添加，或全部替换并按上述规则自动删除本次旧目录副本；PDF 和 JSON 不改动。书签不一致、资源布局未知或页映射不明确时停止，应先生成并替换 PDF 或选用匹配 JSON。

## 清理旧文件与备份

新 PDF、享做目录、跳转和笔迹确认正常后，再决定是否清理。清理会结束清单中备份的恢复能力，不能撤销。

1. 保存笔记并强行停止享做，不清除数据。
2. 点击唯一的“清理旧文件与备份”。弹窗列出完整待删路径／文档地址，以及未通过核验而保留的旧件路径和原因。
3. 核对清单，确认只包含本次任务的旧件；需要原 PDF 备份时，先取消，在“更多操作与恢复”导出备份。
4. 确认清理后，程序整批预检并记录进度，先删除通过核验的外部旧件，最后删除关联的应用内恢复备份，全部核验完成后报告结果。

| 会进入清理清单的范围 | 不删除的范围 |
| --- | --- |
| 本工具成功记录关联且通过核验的同目录旧 PDF、旧目录及对应应用内 PDF／目录恢复备份 | 当前新 PDF、活动 `catalog.json`、`catalog.json.temp`、笔迹、图片、页配置、`.ncc`、其他笔记、来源 JSON及失去关联的未知旧文件 |

仅同步目录的任务可只清理目录备份，不要求存在旧 PDF。全部替换成功后已自动删除本次目录副本，统一清理仍可处理符合条件的剩余 PDF 备份。没有成功关联的旧版、电脑试验或其他任务备份不按文件名、前缀扫描删除。

若享做保存后改变了活动目录，目录旧件组会保留并显示原因；核验合格的独立 PDF 组仍可清理。不要为了清理成功去删除活动目录、`catalog.json.temp` 或笔迹配置。

中断或删除失败会保留剩余文件和原清单进度，按钮变为“继续清理旧文件与备份”；新写入暂时停用。按原清单重试，或在失败／续行弹窗选择“保留剩余文件，结束清理”：程序将精确清单归档至应用内 `cleanup-records/<UUID>.json`，校验后解除待清理标记，剩余文件及关联保留。已经删除的文件不会因此恢复。

## 备份、恢复与未完成任务

展开“更多操作与恢复”可使用“导出最近一次原 PDF 备份”“从备份恢复消失的 PDF…”。这些功能在关联内部备份仍存在时可用；统一清理删除对应恢复备份后，不能再依靠它恢复。其他笔记的备份不因此删除。

- **导出原 PDF 备份**：选择新的保存位置，将最近一次内部原 PDF 备份另存。可在确认清理前操作。
- **恢复消失的 PDF**：先关闭享做，选择原 PDF 所在文件夹，按记录中的原名称恢复并核验。遇到同名但内容不同的文件时停止，不覆盖它。
- **未完成 PDF 替换**：第3节直接显示“恢复上次替换前的原 PDF”。先按提示处理恢复记录；不要卸载或清除应用数据。
- **未完成享做目录同步**：保存并强行停止享做，再使用直接显示的“恢复上次目录同步前的享做目录”。该恢复只处理目录，不回退已成功的新 PDF，不修改笔迹；活动目录已被改写时拒绝覆盖。
- **全部替换目录成功、自动清理未完成**：新目录已经写入；JSON、剩余目录副本和进度保留。按第3节继续清理，或归档清单后保留剩余文件并结束清理。

恢复入口不因“更多操作与恢复”折叠而隐藏。存在未完成替换、同步或清理时，先处理它，程序不会将任务自动当成成功，也不会因此删除 JSON。未完成时保留应用数据、原文件夹和必要材料。

## 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 已授权仍提示需要原文件夹授权 | 单文件授权不等于文件夹授权。授权实际原文件所在目录／父目录，确保可创建和改名；来源不支持时改用另存 |
| 粘贴路径打不开 | 检查是否为平板共享存储路径、完整 PDF 文件名及正确目录；不要粘贴 Windows“此电脑”设备位置。首次使用先授权文件夹，再点使用路径 |
| “No value for schemaVersion” | 当前版本不要求 `schemaVersion`。覆盖安装正式 v0.1.9，保留应用数据；选用下方两种受支持 JSON 格式，再读取核对 |
| 勾选核对后又变为未勾选 | 换输入、改 PDF 书签替换选项、操作完成或失败会清除核对状态，需要重新读取或重新核对；勾选不绕过校验 |
| PDF 有书签却不能生成 | 默认跳过已有书签。确需替换时勾选第2节“替换PDF已有的整棵目录”，再核对并勾确认 |
| 新 PDF 替换成功，享做没有目录 | 确认替换的是详情中的原资源 PDF，不是“带目录”副本；检查享做同步是否成功。PDF 已含匹配书签时可仅同步目录；同步前保存并强行停止享做，完成后重开。不删除旧配置尝试刷新 |
| “尚未核实这个享做目录的页码格式”或页面映射错误 | 当前版本兼容已适配的混合内部页码，但不猜测未知结构。记录具体提示和对应笔记路径，检查输入、实际页码和资源布局；格式错误不需反复授权，也不要删配置 |
| “PDF成功，JSON未删除” | PDF已保存核验成功，JSON因权限或内容变化等原因保留。核对提示；不需把整个PDF任务重做 |
| “新目录已替换，但旧目录清理未完成” | 新目录已写入，旧副本尚未全部删除。保留数据，按同一清单继续清理或保留剩余文件结束清理 |
| 清理按钮不显示、部分旧件不能清理 | 只清理当前成功记录关联且通过核验的旧件。未知旧备份或活动文件已变化时保留；查看原因，不按前缀手工大范围删除 |
| 生成／另存失败 | 原件保留。已生成且核验的结果仍可在更多操作中重试保存；若提示待恢复，先处理恢复记录 |

程序拒绝加密、密码保护、包含签名字段或无法安全处理的 PDF。其他享做版本、移动后的资源布局、未知页映射和所有文件来源并未一概保证兼容；具体错误应按原提示处理，不通过删笔迹或配置来绕过。

## 目录 JSON 与页码映射

### PC 版 `version: 1`

```json
{
  "version": 1,
  "mapping": { "offset": 10 },
  "bookmarks": [
    {
      "title": "第1章 基本概念",
      "page": 1,
      "children": [
        { "title": "1.1 定义", "page": 2 },
        { "title": "附录说明", "pdf_page": 20 }
      ]
    }
  ]
}
```

每项必须且只能提供 `page` 或 `pdf_page`：`page` 是正整数印刷页码，`pdf_page` 是正整数 PDF 实际页码，封面是 PDF 实际第1页。`children` 保留完整多级目录，数组顺序即书签顺序，不限制3–5条一级目录。

`mapping.offset` 满足“PDF 实际页码＝印刷页码＋offset”，可为正、零或负整数，省略 `mapping` 时偏移为0。本例 `page: 1` 跳到实际第11页，`page: 2` 到第12页；`pdf_page: 20` 直接跳第20页，不再应用偏移。

有插页或缺页时可使用分段映射：

```json
"mapping": {
  "segments": [
    { "printed_start": 1, "printed_end": 100, "pdf_start": 11 },
    { "printed_start": 101, "printed_end": 200, "pdf_start": 113 }
  ]
}
```

这是替换顶层 `mapping` 的片段，不是独立 JSON 文件。区间包含两端，计算为 `pdf_start + page - printed_start`；`offset` 和 `segments` 二选一，区间不能重叠，目标不能越过 PDF 总页数，未覆盖的印刷页报错。

PC JSON 顶层只允许 `version`、`mapping`、`bookmarks`，节点只允许 `title`、`page`、`pdf_page`、`children`。`version` 必须是整数1，标题非空且无NUL，页码不能是字符串、小数或布尔值。未知字段、重复字段及错误类型停止处理。

### Jasminum 原生目录

兼容原生 `{ "info": {...}, "outline": [...] }`，读取 `title`、PDF 实际页 `page` 和嵌套 `children`。导入前核对页码从1开始；程序不会自动将全部页码加1。`x/y/collapsed` 等显示信息不决定目标页，也不被解释为总页数。

两种格式均使用 UTF-8，可带 BOM；无需 `schemaVersion`、文档标题或总页数字段。真实总页数从所选 PDF 读取，不取目录最大目标页。空标题、空目录、越界页码或缺失映射会停止。任意 JSON、TXT、Word 或 Excel 不会自动解释成目录。可用仓库 [examples/toc.json](../examples/toc.json) 学习格式。

## 源码与构建

源码入口 `app/src/main`。显示版本由 `VERSION` 统一提供，Gradle 和界面自动同步；实际升级还要递增 `app/build.gradle` 的 `versionCode`。本次正式版调整不改变 APK，不增版本号。

使用 JDK 17、Android SDK 35 和项目 Gradle Wrapper：

```powershell
.\gradlew.bat assembleDebug lintDebug testDebugUnitTest --no-daemon --console=plain
```

也可运行 `scripts/build.ps1 -ToolingRoot '<含 jdk 和 sdk 的工具目录>'`。输出位于 `app/build/outputs/apk/debug/`。本地构建及云端 CI 生成的临时签名包，不等于已有发行签名的升级包；后续正式 APK 必须保持既有签名并核对版本。签名与发布规则见 [MAINTENANCE](MAINTENANCE.md)。

真实混合页码样本回归可传 `-EnjoyMixedFixtureFolder '<含 catalog.json、pageids.json 和 doc 的样本目录>'`；已有434页样本使用 `-EnjoyFixtureFolder`、`-InputJson` 和 `-ActualPageCount`。两组参数也可传给 `scripts/release.ps1`；真实样本仅留本地，不进入公开源码包，没有对应输入的回归不能记为已通过。

使用 `scripts/release.ps1 -OutputDirectory '<工程外的新版本交付目录>'` 完成构建、回归、签名与版本校验及打包。已存在的交付目录会被拒绝，防止覆盖历史包。产物命名为 `PDF_Bookmarks_v{版本}_android.apk`、`PDF_Bookmarks_v{版本}_android_source.zip` 及 `SHA256SUMS.txt`，排除测试书籍、诊断资料和私钥，保留可编辑源码与许可证。

发行 APK 独立运行，不依赖电脑上的源码或测试缓存。原标签与5个发行附件不替换，源码 ZIP 内保留首次发布时的说明；正式版最新使用说明以仓库 `main` 分支的 [README](../README.md) 和本页为准，程序源码与原发行包不变。
