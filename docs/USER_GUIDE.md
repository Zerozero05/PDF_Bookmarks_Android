<a id="v140-流程与界面试用"></a>
## v1.4.0：流程与界面试用

初始先显示选择文件区，分别选PDF与对应JSON；缺一份时提示具体缺项。读取成功后显示核对与输出区域，文件区可收起，仍可更换或重读。底部主按钮随当前阶段提示读取、核对、生成、继续保存或打开结果；有未完成事务时先定位恢复，不重复开始生成。导入提示可以直接进入问题清单；即使目录没有成功解析、只有诊断报告，也可点开详情，详细说明在就近帮助或结果详情查看。

处理选项明确区分以下三个选择，不能互相代替：

| 名称 | 控制内容 |
| --- | --- |
| PDF书签内容 | PDF已有书签时，是否明确替换整棵旧书签树；默认跳过已有书签 |
| PDF保存方式 | 原路径同名替换，或保留原件另存新副本 |
| 享做目录处理 | 仅适用于已识别资源PDF的享做目录：保留并添加，或全部替换；仅同步入口也沿用这项选择 |

选项随普通PDF、另存、原路径替换与同步场景显示；隐藏暂不适用的选项不会替用户重置当前选择。换输入时恢复原有安全默认值：JSON删除关闭、享做目录保留并添加。生成前先只读核对源文件身份、原文件夹授权／声明能力及所选享做结构／映射；提示授权或文件变化时先处理原因，正式保存仍会重新核验。另存位置仍由系统选择，不需要为另存先授权原文件夹。

**已生成不等于已保存。** 取消另存后结果显示等待继续保存，已生成副本保留；从底部或对应结果动作继续保存，不必重新生成。保存成功后显示提供者实际返回的文件名与位置，可能与原建议名不同；用底部主按钮打开已保存PDF。

PDF已保存但享做目录步骤失败时，先看是否有待恢复记录：有记录就按原恢复入口处理；没有待恢复记录且结果提供“仅重试未完成的享做目录同步”时，可只续办该步骤。当前会话的快捷续办重新核对这次实际已保存PDF、来源JSON及本次完整目录和模式，不重新生成／替换PDF，并保留JSON。

离开时，应用继续用原有核对草稿保存当前已调整页码和核对进度，绑定**最终已保存PDF**的文档地址和内容哈希。重开后须重新读取JSON与该最终PDF，核验两份内容、标识及原JSON目录树，符合后才恢复页码工作副本并要求重新确认；危险替换模式和删除选择不自动恢复，也不会自动继续同步。草稿不是旧PDF身份的沿用，不代替原持久事务记录；存在替换、目录同步或清理待恢复时，仍先按原恢复提示处理。

若目录已经成功，只是旧目录副本清理失败，结果会保持“目录成功”，另列清理未完成；关联草稿继续保留，直到清理完成，或明确选择“保留剩余文件，结束清理”并成功结束本次清理后才结束。

如果可选的来源JSON删除失败，可在对应结果选择“保留JSON，结束此可选步骤”。返回／取消不改变当前结果；确认保留只结束这一次可选删除并标记JSON保留，不改动来源文件或授权，也不重做已保存PDF、已同步目录或清理步骤。这与保留剩余备份并结束清理是两个不同操作。

在“检查与变化”打开差异清单，可点变化项定位新条目及当前目标页。定位按来源真实索引，必要时清除阻挡的搜索并展开祖先；同名条目不会按标题随意定位。旧树移除项仅在旧目标可靠时浏览旧页，未知目标保留详情，不新建条目。筛选、定位和预览都不减少最终写入的完整目录。

核对区随实际窗口与字体调整左右／上下排列和占用空间，拖动分隔条仍分别记住两种比例；目录独立滚动，搜索、折叠、缩放、全屏和草稿继续保留。手动翻页与所选目录目标不一致时，页面旁显示“浏览页／所选目录目标”的短提示；浏览不改目录目标，加载、失败和全屏也保留这一区分。

分段调整显示固定的“原起页／原止页／新起页”列头，每个分段一行，行末“×”删除该分段。分段较多时在列头下的编辑区域滚动，删除触控至少48dp。仍须先试算、抽查再明确应用；修改参数后必须重算，取消不应用，“恢复导入页码”保持可用。

顶部“更多”集中外观、版本与更新、使用帮助和许可，原更新控制与备份／恢复功能保留。清理仍从唯一入口进入，先按“将删除／本次保留”核对完整位置、保留原因和恢复影响，再点红色确认动作；不扫描其他任务，不把来源JSON加入旧件清理。

<a id="v130-已授权位置管理"></a>
## v1.3.0：已授权位置管理

在PDF或JSON的“浏览文件”中回到已授权位置根列表，即可管理本工具保存的文档访问授权。**红色按钮是“移除授权”，不会删除文件夹、PDF、JSON或笔记。** 已选文件、核对草稿和处理记录也不会因移除授权自动清空；后续读取或保存仍需重新核对实际访问权限。

1. **单个位置**：向左滑动该行，选择“详情”或红色“移除授权”。不便滑动时使用该行菜单；长按可进入选择模式。查看详情能核对完整位置、原始授权URI和当前读／写范围，也可复制路径。界面的“/内部存储/”用于阅读；系统primary存储实际复制`/storage/emulated/0/…`，其他提供者复制原始content URI，不猜测其磁盘路径。
2. **多个位置**：点击“选择”或长按位置，勾选需要移除的项目；用“全选”“取消全选”调整，已选数量随操作更新。点“完成”退出选择；进入子目录后仍按原单文件浏览／选择，不在文件行批量删除内容。
3. **确认撤权**：点击单项或批量移除后，先核对弹窗中的完整目标清单、每项确切URI及读写范围。确认只移除这些本工具授权，取消则不撤销；执行前会重查系统授权，已变化时停止剩余操作并要求刷新重选。
4. **查看结果**：成功、失败、授权已不存在和未处理分别显示，不把部分成功当全部完成。可刷新列表，再对确切失败项处理；不能按文件路径前缀猜测或连带移除其他父／子授权。

误触时关闭滑出操作、退出选择或使用原“取消选择”返回，不要求先选一个文件。应用正在读取、生成、写入、识别分享、执行系统选择或有未完成替换／目录同步／清理恢复时不能撤权，先完成或取消相应操作；浏览和原取消入口保留，不靠清应用数据解除保护。

**确认并开始撤权后，取消文件列表只关闭列表，已经开始的授权操作仍会继续处理。** 此时主界面的新读取、生成、分享及更新安装继续锁定，完成后按实际成功／失败反馈；不把返回当撤权回滚，也不会自动清空原文件选择或核对进度。

移除授权后，磁盘文件仍存在；需要时用“添加文件夹授权…”重新授权。若另有重叠父目录或子目录授权，原位置仍可能能访问，这不是文件删除失败。复制路径也不会授予权限。不可读位置可查看详情、刷新或重新授权，系统来源和权限失效提示仍按原规则处理。

最终电脑构建318项回归通过、2项旧样本缺失跳过，新增13项授权模型通过；目标API31已安装最终包并通过完整本轮回归，包括2个真实授权根的左滑／竖滚、详情、复制值只读映射、长按／复选／全选、单项／批量确认取消和返回。精确授权、原输入及偏好保持，临时设置已还原并移除本次测试组件。真实撤权／批量执行、重授权、实际剪贴板按钮和菜单刷新仍未实机验证，见[D61–D68](DEVICE_ACCEPTANCE.md#v130-已授权位置管理验收)。测试中的移除确认一律取消，不撤销用户真实授权。

<a id="v120-草稿分享与核对流程"></a>
## v1.2.0：草稿、分享与核对流程

界面继续保持“选择文件 → 核对目录 → 生成结果”，底部始终提供当前步骤的主操作。初始不展开空预览或核对选框，选好文件后从底部读取；读取成功后收起文件区，仍可展开更换或重新读取。第3节首先展示处理摘要，完整路径、目录差异及高级设置按需展开；仅原PDF有书签时显示PDF替换选框。处理后定位分项结果并收起输入与处理选项，不删除文件、改变处理模式或隐藏未完成任务的恢复入口。

### 自动保留核对进度

读取成功后，应用将已应用的目标页调整、搜索词、折叠状态、当前目录项、预览页和目录滚动位置保存为内部核对草稿。没有预览时保持未预览状态，不替用户猜选第1页。重新打开后须重新读取PDF与JSON；应用核对两份文档标识、实际内容SHA-256、原目录树及PDF总页数一致，才恢复相应工作副本。

**草稿不保存“已核对”，也不恢复全部覆盖或删除JSON等处理选择，不自动继续写入。** 恢复后先抽查实际跳转页，再勾选核对并选择本次处理方式。文件已移动、内容变化、授权失效或草稿损坏时，按提示重选、重读并重新核对，不把上一次确认用于新文件；无法保存或恢复草稿会显示原因。

草稿用于恢复核对过程，不能代替PDF／享做目录／清理的事务恢复。若显示未完成替换、同步或清理，仍先按[备份、恢复与未完成任务](#备份恢复与未完成任务)处理原记录，不能靠清草稿、重新生成或清应用数据跳过。

成功同路径替换后，原PDF的内容已变化；开始下一轮调整时应重新读取核对，不能恢复旧内容的草稿。另存后若继续调整工作副本，则重新保存这一轮草稿并重新核对，不沿用上次生成确认。

### 从其他应用分享导入

1. 在支持分享文档的文件应用中选中PDF或JSON，使用系统“分享”，选择“PDF目录工具”。一次可分享一个PDF、一个JSON，或各一个；不接受两个同类型文件、未知文件或网络链接。
2. 核对本工具显示的文件信息，确认后才改变输入；取消时保留此前选择。只分享一份时，再从第1节补齐另一份。
3. 点击读取并核对。分享本身不会生成、替换PDF、同步享做目录或删除来源文件。

分享使用来源提供的content文档地址，不接受网页或私有文件路径。来源可能只给临时读取权限，重开后失效时请重新分享或通过浏览文件选择；同路径替换仍须单独获得原文件夹的创建、改名权限，不能仅靠分享授权执行。

### 检查导入问题与目录差异

导入问题清单给出具体字段位置、目录标题和原因，可复制详情。存在格式或目标页错误时，修正来源JSON后重新读取；重复条目等提示供人工核对，应用不擅自去重，也不自动改写输入。严格字段、类型、页码和重复键规则保持，诊断通过不取消后续文件权限与内容核验。

生成前可只读查看目录差异：**PDF内部书签**与**享做目录**分别对比，显示新增、移除、标题／目标／层级变化及保留数量。PDF仍按第2节的跳过或整棵替换选择处理；享做仍按第3节的保留添加或全部替换模式处理。享做原笔记页无法明确映射到PDF实际页时显示原页标识，不猜测页码；普通PDF不擅自寻找享做笔记。预览不是授权，也不能代替正式操作前再次核对文件身份、映射和权限。

旧PDF可能有未命名或没有可解析目标的书签，预览会明确提示，不能把它们误认为第1页。新导入JSON仍须有非空标题和合法实际目标；看到旧书签提示不代表应用会自动修复原PDF或放宽JSON校验。

### 返回、行详情与处理结果

- 长按目录行查看完整标题、层级、导入目标页与当前目标页；可复制标题或当前页码。复制不会写入目录，列表仍保持标题／目标两栏。
- 系统返回优先处理当前键盘、弹窗、全屏或输入层次，再回到主界面；有调整时保留草稿入口。读取可取消，保存／改名／目录同步／恢复阶段仍按原保护等待结果，不能用返回强行中断写入。
- 生成摘要用于核对目标文件、完整目录数、PDF／享做处理方式与是否删除JSON。完整地址按需展开，不把搜索后显示数量当最终写入数量。
- 处理后定位结果卡片，分别查看PDF、保存、享做、JSON和旧件状态；打开、新件另存重试、备份／恢复及唯一清理入口继续保留。部分失败仍需按具体提示处理，不把PDF已保存写成全部成功。

本轮目标平板已保留数据升级，实际启动／重建、主题字号间距组合、横竖切换、文件选择与空路径取消通过；合成草稿区的恢复／长按详情／返回和内部AtomicFile检查也已通过。真实外部分享与临时授权、主界面真实书籍进程退出后继续核对、分屏／系统字体／手写笔及真实笔记写入仍待单独核对，完整范围见[D52–D60](DEVICE_ACCEPTANCE.md#v120-草稿分享与交互验收)。

## 适用任务与准备

本工具将一本 PDF 和一份已准备的目录 JSON 合成为带完整多级书签的 PDF。它还可为已识别的享做笔记资源同步享做自己的目录，无需开启无障碍服务。文件处理在本地完成，PDF处理可离线完成，不请求全盘访问权限；更新检查需要联网，安装更新需要系统允许此来源。

准备 PDF 与目录 JSON，二者不必同名或放在同一文件夹。JSON 可来自 PC 版目录工具或 Jasminum，格式见下方[目录 JSON 与页码映射](#目录-json-与页码映射)。当前不提供 OCR、自动文字提取、目录编辑工作台或批量处理。

已验收设备为 HUAWEI MatePad Pro 12.2（MRO-W00、HarmonyOS 4.2.0、12 GB RAM、256 GB 存储、2800×1840）。应用最低要求支持 APK 的 Android 8.0／API 26 环境；HarmonyOS NEXT 不属于本版主路线。

## 安装、升级与华为文件授权

1. 从[v1.1.1发行页面](https://github.com/Zerozero05/PDF_Bookmarks_Android/releases/tag/v1.1.1)下载 `PDF_Bookmarks_v1.1.1_android.apk` 和配套 `SHA256SUMS.txt`。可以在平板直接下载，也可以通过数据线传到平板。
2. 在平板文件管理器中打开 APK。若系统询问是否允许该来源安装应用，进入对应设置允许后继续；具体页面名称以当前系统显示为准。
3. 从旧版本升级时选择覆盖安装，保留应用数据。不要先卸载或清除数据：应用内原件备份、恢复记录及文件授权依赖这些数据。正式发行 APK 沿用原升级签名；不要使用 GitHub Actions 的临时构建包覆盖安装。
4. 打开应用“PDF目录工具”。它无需无障碍或全盘访问权限；更新功能需要联网和系统安装来源授权；访问文件时由系统选择器授予所选文件或文件夹权限。
5. 首次粘贴享做路径或执行同路径替换，在“文件夹授权与说明”点击“授权路径所在文件夹”，或在应用内文件列表点击“添加文件夹授权…”。在系统界面选择实际所在目录或其父目录并允许读写，例如“享做笔记/note”；不要尝试授权系统限制的全盘根目录。
6. 授权完成后返回应用，点击“使用此路径”或重新读取。选择错误目录可取消，原来选定的文件保留；程序不会反复自动打开选择器。

**路径不是权限。** 单个 PDF 的写权限不能代替原文件夹的创建、改名权限。文件来源必须支持创建暂存文件及改名，才能同路径替换；不支持时使用另存副本。提供者支持时，应用持久保存授权；授权失效时重新授权对应目录即可。

## 第1节：选择文件、粘贴路径与取消

PDF 原文件和目录 JSON 分为两个区域，各有“浏览文件”和“粘贴路径”。

点击“浏览文件”默认打开应用内列表，列出已授权位置；进入文件夹后只显示文件夹及当前类型的 PDF／JSON，隐藏的 `.note_*.pdf` 仍可见。名称下方及当前位置会显示授权位置，避免混淆同名文件夹。点击文件才提交选择。右上角固定“取消选择”，即使列表为空、正在读取或出错也可退出；“返回上级”只回到已进入的位置，不推断授权外的父目录。

没有授权时，可“添加文件夹授权…”后重新浏览；也可用“更多文件来源（系统）…”保留原有系统文档来源。系统授权与文件界面仍由系统提供，取消方式见下方。文件浏览只使用已授权范围；更新联网不会扩大文档访问权限。

点击相应区域的“粘贴路径”，输入后点“使用此路径”；取消路径编辑不会改变已选文件。浏览、授权不会自动读写 PDF 或 JSON，仍需点击“读取文件并预览目录”。

要更新享做已有笔记，在享做笔记详情中复制 **PDF 路径**。应选择该笔记资源目录里的原 PDF，格式例如：

```text
/享做笔记/note/note_<笔记ID>__res__/.note_<笔记ID>.pdf
```

这只是路径格式，实际使用应粘贴自己的完整笔记路径。不要选择 `.ncc` 笔记文件、资源文件夹本身，或内部存储根目录的“带目录”副本：处理副本不会更新原笔记。

支持共享存储中的 `/享做笔记/...`、`/storage/emulated/0/...`、`/sdcard/...`、`file://` 和已有访问授权的 `content://`。电脑显示的“此电脑\HUAWEI MatePad Pro\内部存储\…”是 Windows 的设备位置，不是 APK 可直接读取的路径；请改用平板详情中的路径或系统选择器。不能用 Windows 盘符或 `/data`、`Android/data`、`Android/obb` 绕过其他应用私有存储限制。

误触或选错时：

- 应用内文件列表：点击固定“取消选择”，或按系统返回，直接回到工具；无需先选择文件。
- 路径输入：点击顶部“取消路径 / 返回”、编辑区的取消按钮，或按系统返回。
- 系统文件／授权／另存选择器：可按系统返回。若系统页没有明显返回控件，先回到系统主屏幕，再点击本工具图标，回到原界面并取消尚未完成的系统选择；顶部也保留“取消系统选择”入口。原文件、核对状态及已生成结果保留，不需要强制重启或清除数据。
- 文件读取：点击顶部“取消读取 / 返回”，或按系统返回，可重新选择并读取。

读取取消不会改动原 PDF 或 JSON。实际保存、改名切换及恢复过程中，应等待核验结果，不以强杀进程作为返回方式。

## 第2节：核对目录与目标页

1. 点击“读取文件并预览目录”（第1节也有“读取 / 重新读取目录”）。程序显示 PDF 实际总页数、完整目录数和已有书签数。
2. 目录固定分为“目录标题”和“目标页”两栏；标题保留层级，可换行，目标为从1开始的 PDF 实际页。目录独立滚动，点击整行预览对应页。
3. v1.1.1可输入标题关键词搜索，清除后恢复完整列表。匹配会保留必要父级，计数区区分匹配、显示和完整数量；搜索及折叠不减少生成或同步的目录。
4. 有子项的目录可点箭头折叠／展开；“更多”中可全部展开、只看一级目录或定位当前目录。搜索期间不能改变折叠状态，避免隐藏匹配。
5. 若 PDF 已有书签，默认跳过生成。确需覆盖时勾选“替换PDF已有的整棵目录”，重新抽查后勾选“我已核对目录标题、层级和实际跳转页”。改变替换选择、应用或恢复页码调整均要求重新核对。

### 预览、窗口和操作

使用 −／＋、双指或双击缩放，放大后可拖动；“适页”恢复整页，“全屏”放大查看，关闭后返回核对区。预览下方可前后翻页，或输入 1 至实际总页数内的页码并点“跳页”。手动翻页只是抽查，不改变目录项的目标。

窗口较宽时目录与预览左右排列，较窄时上下排列；拖动两区之间的分隔条调整空间。两种排列分别记住比例，旋转或分屏调整窗口时保持当前任务。实际小窗、软键盘和触控笔效果仍须设备验收。

| 键盘操作 | 作用 |
| --- | --- |
| Ctrl+F | 定位目录搜索 |
| 搜索框 Enter | 选择第一个匹配项并预览 |
| 页码框 Enter | 跳到填写的 PDF 实际页 |
| +／−／0 | 预览区聚焦且未编辑文本时，放大／缩小／适页 |
| Tab／Shift+Tab、Enter | 使用原生控件焦点移动和激活；仍须核对当前聚焦位置 |

触控笔可用于点选和拖动控件；本工具没有新增笔迹编辑功能。

### 页码调整与抽查（v1.1.1）

若页面落点不对，可在“更多 → 页码调整…”中处理，不必先改来源 JSON。

1. 选择“整体偏移”，填写正、零或负偏移；或选择“分段调整”，每行填写**原实际页起点、原实际页终点、新实际页起点**。分段不能重叠，完整映射范围不能越界，未覆盖的原目标保持不变。
2. 点击“试算并抽查”，查看变化数量并点样例预览新目标页。试算不更改当前已应用目录；修改参数后必须重新试算，错误时保留原有效结果。
3. 确认无误再点“应用并重新核对”。程序更新完整目录工作副本，清除此前核对与生成结果；重新抽查并勾选确认后才可生成。取消不会应用。
4. 需要回退时，在“更多”选择“恢复导入页码”，重新核对；重新读取文件也从来源导入。

**调整基准是导入后已经解析出的 PDF 实际页，不是印刷页码。** JSON 自身的 `mapping` 已在导入时生效，这里的偏移是在其结果上计算。每次试算都使用同一导入基准，不在上次试算或已应用结果上累加；恢复导入页码也不会清除 JSON 原有映射。原JSON始终不改写，工作副本不作为新JSON导出。历史v1.1.1不保存核对草稿；v1.2.0起新增的内部草稿按[上述独立规则](#v120-草稿分享与核对流程)恢复。标题和层级不在这里编辑。

勾选核对不会放宽权限、格式或页映射检查。换输入文件会使旧预览和已生成结果失效；记住上次选定文件不等于已重新加载目录，需要重新读取。历史v1.1.1进程结束后不能依赖搜索或页码工作副本恢复；v1.2.0起使用草稿也必须先重读并验证文件，已核对状态不跨进程沿用。

## 第3节：生成与保存

常用区域显示当前处理设置，成功保存后显示“打开已保存的 PDF”；存在成功关联旧件或未完成清理时才显示唯一清理入口。“处理选项”和“更多操作与恢复”可展开，收起不改变功能。v1.1.1把当前步骤的主按钮固定在底部：先读取，再前往核对，确认后生成／保存，成功后打开；存在待恢复任务时先处理直接显示的恢复入口。

### 默认选项

| 选项 | 默认值 | 作用 |
| --- | --- | --- |
| 直接替换原 PDF（原路径与名称） | 开启 | 替换第1节选定的原 PDF，保持其所在路径与文件名 |
| 替换后同步享做目录 | 开启 | 仅在替换已识别的享做资源 PDF 时同步目录；普通 PDF 不猜测所属笔记 |
| 享做目录处理方式 | 保留已有目录并添加新目录 | 保留手动项和旧项，添加缺少的新项 |
| PDF及所选同步成功后，删除所选 JSON | 关闭 | 满足成功与删除校验条件后，删除这一份来源 JSON |

换输入文件后，JSON 删除恢复关闭、享做目录模式恢复保留并添加。重新创建界面也恢复保留目录模式，避免沿用上次全部替换选择；v1.1.0 的外观及窗口切换不重新创建任务，不替用户更改这两个选择。

### 同路径、同名替换

1. 核对原 PDF 路径。如果要更新享做，先保存笔记，在系统设置中 **强行停止享做，不要清除数据**，让它保持关闭。
2. 保持“直接替换原 PDF”勾选，按需选择享做目录模式和 JSON 删除选项。
3. 点击底部“生成并替换原PDF”，核对确认弹窗中的条目数、目标文件、同步模式及删除范围，再确认执行。
4. 等待程序报告原路径同名替换并核验成功，再打开输出文件；对享做原笔记，重新打开并核对目录、跳转和原笔迹。

程序先在本地副本生成，检查书签、页数及原字节前缀；替换前将原 PDF 保存到应用内 `files/pdf-backups/`，在原文件夹写入并重新读取新暂存 PDF。新件核验成功后，将原件改为唯一备份名，再把新件改为原名，逐阶段保存恢复记录、实际 URI 和内容校验结果。成功后默认保留同目录旧 PDF 与应用内 PDF 备份；只有后续明确清理才删除。

程序不会打开原 PDF 的截断写入流，也不会先删除原文件再生成新文件。两次改名之间可能暂时没有原文件名，该过程是可恢复的改名流程，不等于系统原子替换。文件来源不支持创建／改名，或文件预览后被改变时停止；请依据提示处理，不能靠重复点击绕过检查。

### 另存副本

取消“直接替换原PDF”，核对并点击底部“生成并另存PDF”。生成核验成功后打开系统另存选择器，选择输出位置；取消时已生成副本保留，可用底部保存入口或“更多操作与恢复”的“另存已生成的PDF…”重试，不必重复生成。建议名称为`<原文件名>_带目录.pdf`，可以自行调整；原PDF保留，输出不能选为PDF／JSON输入文件本身。

另存模式不直接同步享做原笔记目录；需要时将保存的新PDF导入享做。保存失败时，原文件和已生成副本保留，可在“更多操作与恢复”使用“另存已生成的PDF…”选择另一位置。已生成结果仍有效时，不必重新生成。

### PDF 书签与享做目录是两个独立选择

- 第2节“替换PDF已有的整棵目录”：控制 PDF 内部书签。默认遇到旧书签时跳过；明确替换时覆盖整棵旧书签树，不合并。
- 第3节“享做目录处理方式”：控制享做自己的 `catalog.json` 目录树。享做可能使用它而不重新读取 PDF 内部书签，所以仅替换 PDF 不一定更新享做界面目录。

| 享做模式 | 成功后的目录 | 旧目录副本 |
| --- | --- | --- |
| 保留已有目录并添加新目录（默认） | 保留已有手动与导入目录，按标题和页标识添加缺少的项；重复同步不重复追加同一项 | 保留本次同目录及应用内目录备份，确认正常后可统一清理 |
| 用新目录替换全部已有目录 | 最终只采用本次 JSON 的标题、层级和目标，全部旧项（包括手动目录）被替换 | 新目录核验成功后自动删除本次外部旧目录及内部目录恢复副本，不能再用它们恢复 |

保留模式下，同名但不同目标页的手动项会与新项并存，无法唯一匹配时停止。全部替换期间仍先使用必要事务副本，写入或清理失败时保留恢复材料；它不先删活动目录再写新目录。清理前显示本次两份目录副本的完整路径，按已经选定的全部替换模式自动删除，不追加第二次确认。**此操作只删除本次两份旧目录副本，PDF 备份不自动删除。**

完全相同的目录树无需重写，不产生本次目录备份，也不删除以前任务的目录备份。两模式均保留目录根字段，不修改笔迹、页面配置或其他笔记。详细格式与页面映射边界见[享做目录同步](ENJOY_DIRECTORY.md)。

### 可选删除来源 JSON

展开“处理选项”，勾选“PDF及所选同步成功后，删除所选 JSON”。只有保存结果核验成功、所选享做同步和相关清理已完成、来源仍是同一份未变化 JSON 且具有删除权限时才执行；否则 JSON 保留并显示原因。

这一选项与统一旧备份清理独立：统一清理不删除来源 JSON。仅同步目录操作不替换 PDF，也不删除 JSON，即使此前勾选了删除 JSON，该独立入口仍保留 JSON。输入切换后删除选项恢复关闭，避免误删下一本书的文件。

### 仅同步当前 PDF 目录到享做

如果当前享做资源 PDF 已含本次 JSON 对应的书签，可在“更多操作与恢复”点击“仅同步当前PDF目录到享做”。须先读取、核对并勾选核对，当前 PDF 与 JSON 的标题、层级和 PDF 实际页逐条一致。

保存笔记并强行停止享做后，在确认弹窗继续。此操作使用同一组享做目录模式：可保留并添加，或全部替换并按上述规则自动删除本次旧目录副本；PDF 和 JSON 不改动。书签不一致、资源布局未知或页映射不明确时停止，应先生成并替换 PDF 或选用匹配 JSON。

### 本次处理结果（v1.1.1）

“本次处理结果”分别列出 PDF 生成、文件保存、享做目录、所选 JSON、旧文件与备份状态。成功、已保留、未执行及未完成分别有自己的含义；例如 PDF 已保存但 JSON 没删，或目录已更新但旧件清理失败，应先查看对应原因。

点“查看详情与文件位置”查看具体原因、实际保存地址并复制详情。阶段提示说明正在读取、生成、核验或写入等真实步骤，不承诺剩余时间。遇到未完成项先按该项提示或恢复入口处理。结果卡片不能代替在 PDF 阅读器／享做中核对目录、跳转及原笔迹。

## 外观设置（v1.1.1）

顶部“外观”（v1.4.0候选位于“更多 → 外观”）可选择跟随系统／浅色／深色、标准／大／更大字号，以及舒适／紧凑间距，点击“应用”生效。设置独立保存；更改时直接更新当前界面，不重新加载文件、不清除核对或重开任务，也不改变享做目录模式、JSON 删除或自动更新设置。紧凑间距仍保留基础点击目标。系统自己提供的授权、另存和安装页面外观由系统控制。

## 清理旧文件与备份

新 PDF、享做目录、跳转和笔迹确认正常后，再决定是否清理。清理会结束清单中备份的恢复能力，不能撤销。

1. 保存笔记并强行停止享做，不清除数据。
2. 点击唯一的“清理旧文件与备份”。弹窗列出完整待删路径／文档地址，以及未通过核验而保留的旧件路径和原因。
3. 核对清单，确认只包含本次任务的旧件；需要原 PDF 备份时，先取消，在“更多操作与恢复”导出备份。
4. 确认清理后，程序整批预检并记录进度，先删除通过核验的外部旧件，最后删除关联的应用内恢复备份，全部核验完成后报告结果。

| 会进入清理清单的范围 | 不删除的范围 |
| --- | --- |
| 本工具成功记录关联且通过核验的同目录旧 PDF、旧目录及对应应用内 PDF／目录恢复备份 | 当前新 PDF、活动 `catalog.json`、`catalog.json.temp`、笔迹、图片、页配置、`.ncc`、其他笔记、来源 JSON及失去关联的未知旧文件 |

仅同步目录的任务可只清理目录备份，不要求存在旧 PDF。全部替换成功后已自动删除本次目录副本，统一清理仍可处理符合条件的剩余 PDF 备份。没有成功关联的旧版、电脑试验或其他任务备份不按文件名、前缀扫描删除。

若享做保存后改变了活动目录，目录旧件组会保留并显示原因；核验合格的独立 PDF 组仍可清理。不要为了清理成功去删除活动目录、`catalog.json.temp` 或笔迹配置。

中断或删除失败会保留剩余文件和原清单进度，按钮变为“继续清理旧文件与备份”；新写入暂时停用。按原清单重试，或在失败／续行弹窗选择“保留剩余文件，结束清理”：程序将精确清单归档至应用内 `cleanup-records/<UUID>.json`，校验后解除待清理标记，剩余文件及关联保留。已经删除的文件不会因此恢复。

## 备份、恢复与未完成任务

展开“更多操作与恢复”可使用“导出最近一次原 PDF 备份”“从备份恢复消失的 PDF…”。这些功能在关联内部备份仍存在时可用；统一清理删除对应恢复备份后，不能再依靠它恢复。其他笔记的备份不因此删除。

- **导出原 PDF 备份**：选择新的保存位置，将最近一次内部原 PDF 备份另存。可在确认清理前操作。
- **恢复消失的 PDF**：先关闭享做，选择原 PDF 所在文件夹，按记录中的原名称恢复并核验。遇到同名但内容不同的文件时停止，不覆盖它。
- **未完成 PDF 替换**：第3节直接显示“恢复上次替换前的原 PDF”。先按提示处理恢复记录；不要卸载或清除应用数据。
- **未完成享做目录同步**：保存并强行停止享做，再使用直接显示的“恢复上次目录同步前的享做目录”。该恢复只处理目录，不回退已成功的新 PDF，不修改笔迹；活动目录已被改写时拒绝覆盖。
- **全部替换目录成功、自动清理未完成**：新目录已经写入；JSON、剩余目录副本和进度保留。按第3节继续清理，或归档清单后保留剩余文件并结束清理。

恢复入口不因“更多操作与恢复”折叠而隐藏。存在未完成替换、同步或清理时，先处理它，程序不会将任务自动当成成功，也不会因此删除 JSON。未完成时保留应用数据、原文件夹和必要材料。

## 常见问题

| 现象 | 处理方法 |
| --- | --- |
| v1.1.0 安装成功后点击图标闪退或白屏 | 已确认目标平板上的系统栏初始化时机错误。保留应用数据，使用提供的原签名 v1.1.1 正式版覆盖安装；不要卸载、清数据或删除 PDF／JSON／笔记配置。修复启动结果见[专门验收](DEVICE_ACCEPTANCE.md#v111-启动修复验收)，公开下载为 v1.1.1 |
| 已授权仍提示需要原文件夹授权 | 单文件授权不等于文件夹授权。授权实际原文件所在目录／父目录，确保可创建和改名；来源不支持时改用另存 |
| 粘贴路径打不开 | 检查是否为平板共享存储路径、完整 PDF 文件名及正确目录；不要粘贴 Windows“此电脑”设备位置。首次使用先授权文件夹，再点使用路径 |
| “No value for schemaVersion” | 当前版本不要求 `schemaVersion`。覆盖安装当前正式版，保留应用数据；选用下方两种受支持 JSON 格式，再读取核对 |
| 勾选核对后又变为未勾选 | 换输入、改 PDF 书签替换选项、应用／恢复页码调整、操作完成或失败会清除核对状态，需要重新读取或核对；搜索、折叠和外观切换本身不清除确认，勾选也不绕过校验 |
| PDF 有书签却不能生成 | 默认跳过已有书签。确需替换时勾选第2节“替换PDF已有的整棵目录”，再核对并勾确认 |
| 新 PDF 替换成功，享做没有目录 | 确认替换的是详情中的原资源 PDF，不是“带目录”副本；检查享做同步是否成功。PDF 已含匹配书签时可仅同步目录；同步前保存并强行停止享做，完成后重开。不删除旧配置尝试刷新 |
| “尚未核实这个享做目录的页码格式”或页面映射错误 | 当前版本兼容已适配的混合内部页码，但不猜测未知结构。记录具体提示和对应笔记路径，检查输入、实际页码和资源布局；格式错误不需反复授权，也不要删配置 |
| “PDF成功，JSON未删除” | PDF已保存核验成功，JSON因权限或内容变化等原因保留。核对提示；不需把整个PDF任务重做 |
| “新目录已替换，但旧目录清理未完成” | 新目录已写入，旧副本尚未全部删除。保留数据，按同一清单继续清理或保留剩余文件结束清理 |
| 清理按钮不显示、部分旧件不能清理 | 只清理当前成功记录关联且通过核验的旧件。未知旧备份或活动文件已变化时保留；查看原因，不按前缀手工大范围删除 |
| 生成／另存失败 | 原件保留。已生成且核验的结果仍可在更多操作中重试保存；若提示待恢复，先处理恢复记录 |

程序拒绝加密、密码保护、包含签名字段或无法安全处理的 PDF。其他享做版本、移动后的资源布局、未知页映射和所有文件来源并未一概保证兼容；具体错误应按原提示处理，不通过删笔迹或配置来绕过。

## 目录 JSON 与页码映射

### PC 版 `version: 1`

```json
{
  "version": 1,
  "mapping": { "offset": 10 },
  "bookmarks": [
    {
      "title": "第1章 基本概念",
      "page": 1,
      "children": [
        { "title": "1.1 定义", "page": 2 },
        { "title": "附录说明", "pdf_page": 20 }
      ]
    }
  ]
}
```

每项必须且只能提供 `page` 或 `pdf_page`：`page` 是正整数印刷页码，`pdf_page` 是正整数 PDF 实际页码，封面是 PDF 实际第1页。`children` 保留完整多级目录，数组顺序即书签顺序，不限制3–5条一级目录。

`mapping.offset` 满足“PDF 实际页码＝印刷页码＋offset”，可为正、零或负整数，省略 `mapping` 时偏移为0。本例 `page: 1` 跳到实际第11页，`page: 2` 到第12页；`pdf_page: 20` 直接跳第20页，不再应用偏移。

有插页或缺页时可使用分段映射：

```json
"mapping": {
  "segments": [
    { "printed_start": 1, "printed_end": 100, "pdf_start": 11 },
    { "printed_start": 101, "printed_end": 200, "pdf_start": 113 }
  ]
}
```

这是替换顶层 `mapping` 的片段，不是独立 JSON 文件。区间包含两端，计算为 `pdf_start + page - printed_start`；`offset` 和 `segments` 二选一，区间不能重叠，目标不能越过 PDF 总页数，未覆盖的印刷页报错。

PC JSON 顶层只允许 `version`、`mapping`、`bookmarks`，节点只允许 `title`、`page`、`pdf_page`、`children`。`version` 必须是整数1，标题非空且无NUL，页码不能是字符串、小数或布尔值。未知字段、重复字段及错误类型停止处理。

### Jasminum 原生目录

兼容原生 `{ "info": {...}, "outline": [...] }`，读取 `title`、PDF 实际页 `page` 和嵌套 `children`。导入前核对页码从1开始；程序不会自动将全部页码加1。`x/y/collapsed` 等显示信息不决定目标页，也不被解释为总页数。

两种格式均使用 UTF-8，可带 BOM；无需 `schemaVersion`、文档标题或总页数字段。真实总页数从所选 PDF 读取，不取目录最大目标页。空标题、空目录、越界页码或缺失映射会停止。任意 JSON、TXT、Word 或 Excel 不会自动解释成目录。可用仓库 [examples/toc.json](../examples/toc.json) 学习格式。

## 自动检测与安装更新

打开底部“版本与更新 · v1.1.1”。默认启动／回到前台时每天最多自动检查一次，也可随时手动检查；可关闭自动检查。发现本仓库更高正式版后查看说明、确认下载，校验成功再点“安装更新”。首次可能需要系统允许此来源；授权返回后再次点击安装，按系统界面确认。更新保留应用数据与文档，不强制退出正在工作的程序。

检查和下载可取消；离线时PDF功能仍可使用。安装前请完成PDF／目录写入、恢复和清理，并退出文件选择或路径输入；未完成任务时程序会停止发起安装。完整下载重开后重新校验，系统回收缓存后需要重下；下载中断目前重新下载。首次从不含更新器的旧版升级仍需手动覆盖安装。

完整功能、权限、故障处理及以后发布规则见[自动更新说明](AUTO_UPDATE.md)。系统授权和真实安装仍需[设备验收](DEVICE_ACCEPTANCE.md#v100-更新流程验收)。

## 源码与构建

源码入口 `app/src/main`。显示版本由 `VERSION` 统一提供，Gradle 和界面自动同步；实际升级还要递增 `app/build.gradle` 的 `versionCode`。本次正式版调整不改变 APK，不增版本号。

使用 JDK 17、Android SDK 35 和项目 Gradle Wrapper：

```powershell
.\gradlew.bat assembleDebug lintDebug testDebugUnitTest --no-daemon --console=plain
```

也可运行 `scripts/build.ps1 -ToolingRoot '<含 jdk 和 sdk 的工具目录>'`。输出位于 `app/build/outputs/apk/debug/`。本地构建及云端 CI 生成的临时签名包，不等于已有发行签名的升级包；后续正式 APK 必须保持既有签名并核对版本。签名与发布规则见 [MAINTENANCE](MAINTENANCE.md)。

真实混合页码样本回归可传 `-EnjoyMixedFixtureFolder '<含 catalog.json、pageids.json 和 doc 的样本目录>'`；已有434页样本使用 `-EnjoyFixtureFolder`、`-InputJson` 和 `-ActualPageCount`。两组参数也可传给 `scripts/release.ps1`；真实样本仅留本地，不进入公开源码包，没有对应输入的回归不能记为已通过。

使用 `scripts/release.ps1 -OutputDirectory '<工程外的新版本交付目录>'` 完成构建、回归、签名与版本校验及打包。已存在的交付目录会被拒绝，防止覆盖历史包。产物命名为 `PDF_Bookmarks_v{版本}_android.apk`、`PDF_Bookmarks_v{版本}_android_source.zip` 及 `SHA256SUMS.txt`，排除测试书籍、诊断资料和私钥，保留可编辑源码与许可证。

发行 APK 独立运行，不依赖电脑上的源码或测试缓存。原标签与5个发行附件不替换，源码 ZIP 内保留首次发布时的说明；正式版最新使用说明以仓库 `main` 分支的 [README](../README.md) 和本页为准，程序源码与原发行包不变。
