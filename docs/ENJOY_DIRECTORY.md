# 享做目录同步与旧备份清理

当前版本为 **v0.1.9 正式版**。2026-10-09，用户反馈「我已验收」并要求正式发布；本次按该总体验收反馈晋级，原 APK、签名、版本号与功能保持。D01–D18 未收到独立逐项记录，不将总体反馈扩展为其他设备、享做版本、云同步或所有故障情形已验证；使用前仍按以下步骤保护笔记。

v0.1.5 增加默认勾选的“替换后同步享做目录（备份、保留手动目录）”。单笔记实测已证明：PDF 内有书签时，享做仍可能使用独立的 `catalog.json`；将目录正确合并到该文件后，用户确认目录、跳转和原笔迹正常。`catalog.json.temp` 是前一版目录，不能当作缓存删除。

v0.1.6 修复旧目录混合内部页码导致的格式报错，并区分格式错误与授权不足。原替换、合并、备份、恢复和手动清理机制保留。

v0.1.7 在第3节增加两个互斥选项：默认“保留已有目录并添加新目录”；也可选择“用新目录替换全部已有目录（原目录备份）”。后者会替换当前笔记全部享做目录，包括手动目录与之前导入的目录，最终只保留本次JSON所列树。两个模式均先核实结构与页面映射，保留原根字段，并沿用原字节备份及中断恢复流程；不修改笔迹、页面配置或其他笔记。

v0.1.8 将第3节改为常用生成、打开结果及一个“清理旧文件与备份”入口。“处理选项”折叠保留原路径替换、享做同步、目录保留或全部替换及 JSON 可选删除；“更多操作与恢复”折叠保留重试保存已生成 PDF、仅同步目录、导出原 PDF 备份及恢复消失的 PDF。未完成 PDF 替换或目录同步的恢复入口仍直接显示。按用户明确授权，统一清理包括本次任务关联的外部旧 PDF/目录备份及对应应用内恢复备份；清理后不能用这些备份恢复。

v0.1.9 仅调整全部替换模式：当前选项为“用新目录替换全部已有目录（不保留旧目录备份）”。新目录写入并核验成功后，自动删除本次外部旧目录备份及内部目录恢复副本，成功不保留旧目录备份。事务写入期间及失败时仍保留必要恢复材料，不能先删旧目录再写新目录。默认保留并添加模式、PDF备份、JSON选项、统一清理及其他功能不变。

## 使用步骤

1. 保存笔记，在平板系统设置中强行停止享做，保持关闭；不要清除数据。
2. 在工具中选择享做详情所列的原资源 PDF 和对应 JSON，授权其原文件夹，读取并核对目录与页码。
3. 展开“处理选项”，保持默认同步勾选，在其下选择保留并添加或全部替换，确认弹窗会列明范围。生成并替换会先检查享做格式与页面映射，备份原 PDF，核验同名新 PDF，再按所选模式更新享做目录。保留并添加模式保留原目录备份；全部替换核验成功后先显示本次旧目录两份副本的完整路径，再按所选模式自动删除，无需第二次确认，不能用已删副本恢复旧目录。若只是给已处理 PDF 更新享做目录，在“更多操作与恢复”中点“仅同步当前PDF的目录到享做”；也使用相同模式和旧目录清理规则，但要求当前 PDF 的书签与 JSON 的标题、层级、物理页逐条相同，不替换 PDF，也不删除 JSON。换任一输入或重建界面时默认回到保留模式。
4. 完成后重新打开享做，核对目录、跳转与笔迹，再保存、退出并重开验证持久保留。目录同步失败与 PDF 替换成功分别显示；失败时保留 JSON 与必要恢复材料，处理恢复记录后再试。若提示“新目录已替换，但旧目录清理未完成”，新目录已写入，剩余旧副本和清理进度保留，按第3节继续清理或归档后保留剩余文件并结束清理。
5. 需要清理时，先核对正常，再保存并强行停止享做。点击“清理旧文件与备份”，核对弹窗的待删清单、未通过核验而保留的旧件完整路径和原因，以及无法再用已删备份恢复的提示，再一次确认；取消不会清理。待删清单只包含当前任务有成功关联并通过核验的旧 PDF、旧目录和对应应用内备份；仅同步目录的任务无需存在 PDF 旧备份。

若提示格式或页映射错误，先返回按实际原因处理并重新读取核对，不需重复授权。程序仅在明确缺少或失效的文件夹读写授权时显示授权按钮。v0.1.5的混合页码错误发生于prepare只读检查，原PDF和活动目录尚未写入；覆盖升级后可重新核对并尝试，无需删除旧目录或笔记配置。

## 适配与保护边界

当前只识别共享内部存储 `享做笔记/note/<笔记ID>__res__/<同笔记ID>.pdf`（PDF 可以带开头点）的资源布局，依据本次享做 7.0.2 单笔记样本。普通独立 PDF 继续只写标准书签。其他提供者、移动后的布局或未知元数据不猜测原笔记。

页面按 `pageids.json` 中匹配该 PDF 的 `document + docIndex` 关联 `pageId`，并与 `doc.pages` 的 ID 和 index 交叉核对。不能用 `pageids` 的数组位置或 index 当 PDF 页序。无映射、重复映射、越界或结构不符会拒绝写入；本次样本的 PDF 第1页没有明确映射，因此这类目标不能猜测。

享做目录根节点内部 `page` 仍必须为-1；已有非根节点允许-1或非负整数，但仍须明确非空 `pageId`。这些旧 `page` 数值完整保留，不解释为导入JSON的页码，也不据此推导缺失的页映射。新增节点继续使用 `page=-1` 和明确的页标识。未知负值、错误数字类型、空子节点页标识等仍拒绝处理；未适配只有数字页码而无页标识的其他笔记格式。

保留模式合并保留原根字段（包括 usn/dirty/expand）、已有手动节点及未知附加字段，只增加缺少的目录及子目录。同一父节点内以标题和 pageId 共同匹配，重复执行不重复追加；同名不同页的手动节点全部保留。无法唯一匹配时停止。替换模式只替换根的kids树，保留所有根字段，不按标题保留旧子节点；原树仅作为事务与失败恢复副本，全部替换核验成功后自动删除本次两份目录副本。两个模式均不会主动更新云同步计数或页面版本字段。

保留模式下，若旧手动条目与JSON标题相同但目标页不同，两项会并存。若用户明确选择全部替换，最终目录完全采用新JSON的标题、层级与目标，不保留这些旧项。该选择与第2节“替换PDF已有的整棵目录”不同：第2节控制PDF内部书签，第3节控制享做自己的目录树。

程序只写当前笔记的 `catalog.json`，保留 `catalog.json.temp`、`pageids.json`、`page_usn.json`、`doc`、`paths`、`.ncc`、笔迹和图片及其他笔记。写入前重新核验文件身份、内容和 PDF；先写新暂存 JSON、回读，再将旧目录改名为备份、新件改为活动目录，并同步保存阶段日志。这是可恢复的两次改名，不能称为系统原子操作。

## 清理与恢复

全部替换的自动清理只接受本次新创建并持久关联的目录副本：同目录的 `pdf-bookmarks-catalog-<UUID>-backup.json` 及对应应用内目录恢复副本。新目录核验后，先保存自动清理意图及精确进度，界面显示两份副本的完整路径，然后重查当前PDF、活动目录及待删副本，先删除外部旧目录，再删除内部目录副本，核验完成后关闭本次目录关联。所选全部替换模式已授权该删除，不再增加确认弹窗。不会删除PDF备份、活动目录/temp或笔迹；保留并添加模式不走自动清理。完全相同的目录树不重写、不产生本次副本，也不删除已有历史目录关联。

若在保存意图、显示清单、删除或完成记录阶段失败，不能报告全部成功；持久记录和剩余副本保留，JSON不按成功选项删除。重启后即使中断发生于新目录成功记录落盘与清理进度保存之间，仍能找到自动清理意图，阻止新写入并提供按原范围继续清理的入口。用户也可按下面的归档流程保留剩余文件并结束清理；已删除副本无法恢复。相关故障回归已在宿主完成，用户提供了目标平板总体验收反馈；没有独立的实机掉电、权限失效或提供者故障演练记录。

统一清理只接受本工具持久成功记录关联的精确目标。目录侧包括同目录的 `pdf-bookmarks-catalog-<UUID>-backup.json` 和关联应用内原目录备份；若当前任务还有 PDF 替换成功记录，同时列出其同目录旧 PDF 和关联应用内原 PDF 备份。先显示完整清单，由用户一次确认。当前目录、temp、新 PDF、笔迹、页面配置、来源 JSON 和其他笔记均保留；JSON 可选删除由另一设置独立控制。用户于2026-10-09明确授权清理上述关联内部备份，这替代旧版“旧件清理时始终保留内部备份”的行为，清理后不能再依靠这些备份恢复。

首次整理清单时分别只读核验 PDF 组和目录组，未通过或已经失效的组明确保留，确认弹窗及完成提示列出其完整旧件路径和原因；没有合格组时全部保留。通过核验的组组成待删除清单，对该清单整体再预检并持久保存清理快照，核实当前活动文件以及每个待删副本的身份和内容，再先处理全部外部旧备份，之后删除对应应用内恢复备份。每阶段重查成功记录和活动文件；待删清单中全部旧副本删除并完成核验后，才关闭其成功关联及清理记录，未通过组的文件和关联保留。

若发生中断、清理开始后的文件变化、权限失效或记录保存失败，保留剩余文件和清理进度，重新打开后可按原清单核验并继续；不会把部分完成显示为全部清理成功。失败或续行弹窗提供“保留剩余文件，结束清理”：先将完整清单写入应用内 `cleanup-records/<UUID>.json`，同步落盘并回读校验，再只清除待清理标记。剩余文件及完整关联记录保留，其他任务重新可用；已删除的旧件不会恢复，无法核验的剩余旧件仍不删除。

没有按前缀扫描删除功能；电脑验证或旧版生成的无关联备份不会被猜测清理。旧版单独清理外部备份后已经移除关联记录的内部文件，也不会仅凭文件名推断归属。

享做重新保存可能改变活动目录内容或标识：首次预检时该目录组会保留并列出原因；若它已进入确认的待删清单，清理中再变化则停止继续删除。不能为了让按钮成功而删除活动目录或放宽核验。

再次替换 PDF 而目录已经完全相同时，不创建新的目录备份关联；旧关联中的 PDF 指纹可能因此失效。首次预检将该目录组明确保留，不阻止独立核验合格的 PDF 组进入待删清单；未核验目录旧件及关联记录不删除。旧任务、电脑单笔记试验产生的备份不会自动纳入清理。

同步中断后第3节直接出现目录恢复按钮，并阻止新替换、同步与清理；不会因收起更多操作而隐藏。保存并停止享做后可恢复同步前目录；该操作不回退已成功的新 PDF、不修改笔迹，并保留暂存件和备份。现有文件已变化时拒绝覆盖。统一清理未完成时也阻止新写入，并提示继续清理；可以按上面的“保留剩余文件，结束清理”保全剩余文件并解除该清理任务的阻塞。确认清理之前，不要卸载工具或清除其数据，应用内备份及日志是恢复依赖；确认清理删除关联内部备份后，该批恢复能力随之结束。

## 验收依据与验证局限

历史单笔记的 72 条目录（2 条手动＋70 条书籍目录）、PDF 第12页跳转和原笔迹已有用户实测；295 份原文件回读中仅活动目录改变，其他294份哈希不变。v0.1.6另以只读344页混合页码笔记复现并修复格式错误，140项宿主回归通过；v0.1.7的145项宿主回归通过。用户的v0.1.7截图可确认模式选项已显示、界面曾显示旧目录备份删除结果，这些属于历史有限证据。

v0.1.9 发布前的178项宿主回归通过；该本地验证阶段没有向平板写文件或运行 APK，不将宿主结果当作设备测试。随后用户于2026-10-09明确反馈「我已验收」，据此确认当前目标平板总体验收完成并将同一发行包晋级正式版。该新增用户报告与此前本地验证阶段的未实机操作记录分别保留，不推断 D01–D18 各项均单独执行。

其他设备、其他享做版本、云同步，以及掉电、删除权限失效等实机故障情形没有独立验证记录。目录全部替换和统一清理会按上文范围删除不可恢复的旧件，每次处理完成仍应重开原笔记核对目录、跳转及笔迹；未知格式、映射或文件变化时保持停止规则。
