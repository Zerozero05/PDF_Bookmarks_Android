## 输入校验约定

PC JSON 顶层只允许 `version`、`mapping`、`bookmarks`，节点只允许 `title`、`page`、`pdf_page`、`children`。`version` 必须为整数 1。标题非空且不含 NUL，页码必须为整数，不能是字符串、小数或布尔值。重复字段和未知字段不会被忽略。

Jasminum 原生缓存是明确的兼容入口，不意味着允许 PC 格式随意增加字段。`info` 是来源元数据，`outline` 保存节点；`x/y/collapsed` 不用于自动点击，也不被解释为 PDF 总页数。层级取自 `children`，不能把子目录压成一级。

每一目标都须落在所选 PDF 的 1 至实际总页数范围内。示例书包含 434 页、Jasminum 目录含 9 个根节点和 70 个总条目，最大目录目标为 429；这些数字分别表示 PDF 总页数、目录数量与最大目录目标，不能互相替代。样本目录不作为公开源码中的测试数据。

## 保存与检查的边界

Android 默认选择原路径、原名称替换，仍需生成前确认；取消替换项可另存副本。替换必须有原文件夹的持久读写 tree 授权，只有原文件读写授权时停止并提示授权文件夹。先在原文件夹写好并核验新 PDF，再将原件改名为备份、新文件改为原名；没有截断原件的写入接口，默认保留原件备份。

第3节保留常用生成、打开结果和“清理旧文件与备份”入口。“处理选项”中可选择原路径替换、享做同步、享做目录保留或全部替换，以及成功后是否删除所选 JSON；“更多操作与恢复”中保留已生成 PDF 的重试保存、仅同步当前目录、导出最近备份和从备份恢复消失的 PDF。未完成 PDF 替换或享做同步时，恢复入口仍直接显示；折叠布局不改变原有保存和恢复流程。

用户确认新 PDF、享做目录与笔迹正常后，可用一个清理按钮统一处理本次任务关联的旧文件。弹窗先列出完整路径或文档地址，范围限于持久成功记录中的同目录旧 PDF、旧目录及对应应用内恢复备份。用户于2026-10-09明确授权将这些内部恢复备份也一起清理；确认后不能再依靠已删除的备份恢复。当前 PDF、活动 `catalog.json`、`catalog.json.temp`、笔迹、页面配置及来源 JSON 不属于该清理范围，JSON 的可选删除仍单独控制。

首次整理清单时分别核验 PDF 组和目录组，未通过或已经失效的组保留，确认弹窗及完成提示均列出它们的完整旧件路径和原因；不会悄悄跳过或删除。通过核验的组组成待删除清单，再对整份清单一起预检，持久保存精确记录，先删外部旧备份、后删应用内备份。每个阶段重查当前文件身份和内容，全部完成后才关闭该清单的成功关联和清理记录。重复替换 PDF 而享做目录无需重写时，旧目录关联的 PDF 指纹可能失效；该目录组保留，但不阻止核验合格的 PDF 组清理。

中断或清理开始后的文件变化会停止继续删除，剩余文件和进度保留，重启后可按原清单重新核验并继续。失败或续行弹窗也可选择“保留剩余文件，结束清理”：完整清单保存为应用内 `cleanup-records/<UUID>.json`，写入同步并回读校验后只解除待清理标记，剩余文件及关联保留，可继续其他任务；已删除项不会恢复，无法核验的剩余旧件仍不删除。旧版未记录身份、已失去关联的备份不由目录扫描或文件名推断，也不会在成功保存时自动删除。

v0.1.9仅对享做全部替换模式自动清理本次两份旧目录副本：新目录写入并核验后，先持久保存意图和进度、显示两路径，再核验和删除；成功不保留目录备份。事务过程中仍使用恢复副本，不能先删后写。自动清理失败显示新目录已替换而旧副本清理未完成，保留JSON、剩余材料及进度，仍可按同一清单续行或归档结束。PDF备份、默认保留并添加模式及统一清理规则不变，完全相同目录树无需重写时不清理旧任务关联。

两次改名不能称为原子替换；每步记录可恢复状态，查找当前精确文件名并核对内容，保存改名后的实际 URI。改名可能改变文档标识和旧授权，享做重新读取底层文件、目录缓存和原批注的行为未验证；先关闭笔记再替换、重新打开核对，必要时重新导入。应用不修改享做私有数据库。JSON只在最终原名文件核验成功并处理恢复记录后删除。

本地生成前拒绝加密/密码保护、签名或无法安全处理的 PDF。生成后重新读取结果，检查书签标题、层级、实际目标页及 PDF 页数和页面内容。生成检查不等于对所有第三方阅读器和享做导入后的显示进行了实测；目标平板上的打开、目录跳转与原批注显示仍需用户验收。
