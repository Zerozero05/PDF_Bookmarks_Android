# PDF 书签目录工具 Android

在 Android 平板上把 PDF 和目录 JSON 合成为带完整多级书签的 PDF，并同步已识别的享做笔记目录。无需无障碍服务，文件在本地处理。

公开发行仍为个人测试版：本地178项回归通过，目标平板新版完整验收尚未完成。目标系统为支持APK的HarmonyOS 4.2，HarmonyOS NEXT不在本版主路线。升级请覆盖安装并保留应用数据；下载包沿用原签名，云端CI临时包不用于覆盖升级。

当前 **v0.1.9 本地测试版**：选择或粘贴 PDF、目录 JSON 的路径，以「目录标题｜目标页」两栏核对多级目录并预览页面。默认保持原路径、原名称替换 PDF，并对已识别的享做资源文件默认同步享做目录。第3节可选择默认“保留已有目录并添加新目录”，或“用新目录替换全部已有目录（不保留旧目录备份）”；后者包括旧手动目录，最终采用新JSON目录树。全部替换核验成功后自动删除本次外部旧目录备份及内部目录恢复副本，成功不保留它们；写入或清理未完成时保留必要恢复材料。保留并添加模式的目录备份、PDF备份及其他功能不变。两模式均保留笔迹和其他配置，支持仅同步已含相同书签的 PDF，第3节将处理选项和更多操作收起；一个“清理旧文件与备份”按钮仍可在列明完整清单并确认后，统一删除本次成功记录关联的剩余旧PDF、旧目录和应用内恢复备份，清理后不能再使用它们恢复。活动文件与笔迹保留。详见[享做目录同步](docs/ENJOY_DIRECTORY.md)。

v0.1.6 修复已授权、已核对后仍提示“尚未核实这个享做目录的页码格式”的问题：兼容旧目录中混合保存的内部页码，保留其原值与手动节点。格式错误不会再引导重复授权；只有真正缺少或失效的文件夹授权才显示授权按钮。此错误原先发生在替换前的只读检查阶段，本次修复不采用删除旧配置的方式。

本轮构建与回归的实际结果见 [VALIDATION.md](VALIDATION.md)，目标平板仍待设备验收。两栏显示、整行点击、文件夹授权、手动删除旧备份及享做重新读取须在平板上核对。

这版对应 PC 工具的「PDF + JSON 写入内部书签」流程。它不是全部 PC 功能的移植：自动文字/OCR 识别、批量处理和完整目录工作台尚未实现，详见 [功能对照](docs/FEATURES.md)。

目标设备：HUAWEI MatePad Pro 12.2，MRO-W00，HarmonyOS 4.2.0，12 GB RAM、256 GB 存储、2800×1840。应用要求 Android 8.0/API 26 或更高的 APK 运行环境。构建与本地验证不代替目标平板的安装、保存及享做导入实测。

## 安装与使用

1. 将通过校验的 `PDF_Bookmarks_v0.1.9_android.apk` 下载或传到平板，用文件管理器打开，覆盖安装到此前版本；不要先卸载或清除应用数据，以免丢失内部备份及恢复记录。若系统询问是否允许该来源安装应用，按系统提示授权后安装。
2. 打开「PDF目录工具」，选择原 PDF 和目录 JSON，或点击各自的「粘贴路径」。核对界面显示的实际路径：要更新享做原笔记，应选择「享做笔记/note」中对应笔记的原 PDF，不要把内部存储根目录的「带目录」副本当成原笔记文件。路径首次使用需授权包含文件的文件夹，例如「享做笔记/note」；授权后可直接粘贴其中的其他文件路径。两者不必同名或同目录。
3. 路径输入可点「取消路径输入 / 返回」或系统返回；系统选择器可按系统返回取消，原来的选择保留。读取文件时可点顶部「取消读取 / 返回」或系统返回。读取完成后查看真实总页数及「目录标题｜目标页」两栏；标题保留层级缩进并可换行，目标页独立靠右显示 PDF 实际页码，表头固定。目录区域可单独上下滑动，点击整行的标题或页码均可查看目标页面，旁边的 PDF 页面预览保留。记住上次文件不会自动加载目录，未加载时显示提示。
4. 默认遇到已有书签时跳过。确需更新时，明确选择替换；替换会覆盖整棵旧目录树，不会与旧书签合并。
5. 默认勾选第3节「直接替换原 PDF」，先关闭享做中的该笔记，再确认生成。首次同名替换必须授权原文件所在文件夹并允许读写；单个文件的写授权不足以创建同目录暂存文件。程序先备份并核验新文件，再切换名称；原件保留为同目录备份，不截断或删除原 PDF。若文件来源不支持创建和改名，取消此项，另存新 PDF。
6. 展开第3节「处理选项」可切换同名替换/另存、享做目录保留添加/全部替换。如需清理目录 JSON，勾选「PDF及所选同步成功后，删除所选 JSON」。该项默认关闭，换输入文件时重置；只有输出校验成功、JSON内容未变化且来源允许删除时执行。失败会明确提示，JSON保留。
7. 另存模式将新 PDF 导入享做。替换享做原资源时，默认同步目录：先保存笔记并在系统设置强行停止享做，不清除数据。在第3节选择默认保留旧目录并添加，或用新JSON替换全部已有享做目录（包括手动项）。保留并添加模式保留原目录备份；全部替换在新目录写入并核验成功后，先显示本次两份旧目录副本的完整路径，再按已选择的模式自动删除，不新增确认步骤，成功不保留目录备份。写入过程仍使用必要事务副本，失败时保留以供恢复，不能先删旧目录再写新目录。两模式均不修改私有数据库、笔迹、temp 或其他配置；PDF备份保持原样。格式未知或页面映射不明确时停止。完成后重开享做核对；已有相同书签可按同一模式仅同步目录。换文件或重开程序后恢复保留默认，确认弹窗会列明是否覆盖手动目录及成功后不可恢复旧目录。详见[适配和恢复边界](docs/ENJOY_DIRECTORY.md)。
8. 在享做核对新PDF、目录、跳转和原笔迹正常后，保存并强行停止享做，点击唯一的「清理旧文件与备份」。先核对完整路径或文档地址清单，再一次确认删除；整批预检通过、成功快照和当前文件未变才执行。外部旧PDF/旧目录全部删除并核验后，最后删除清单中的应用内恢复备份，清理后不能用它们恢复。当前PDF、活动catalog/temp、笔迹/页配置、原始JSON和其他文件保留。旧版已经失去关联的备份无法确认归属，保留且不扫描。失败留下原清单和进度，可按「继续清理旧文件与备份」重试。
9. 展开「更多操作与恢复」可仅同步当前PDF目录、另存/重试保存已生成PDF、导出原PDF备份或恢复消失PDF；另存生成或保存失败时自动展开。未完成PDF替换/目录同步的恢复入口直接显示。清理删除了对应内部备份后，导出/恢复入口随记录移除；其他笔记备份保留。

文件选择授权针对所选文档/文件夹，应用在提供者支持时持久化读写授权，不要求无障碍服务、全盘权限或联网。路径支持截图中的 `/享做笔记/...`、`/storage/emulated/0/...`、`/sdcard/...`、`file://` 和已有授权的 `content://`。路径不是授权：普通路径只在既有 SAF 授权范围内转换，不绕过系统访问限制；`/data`、`Android/data`、`Android/obb` 及 Windows 盘符不能用来访问其他应用私有文件。官方规则见 [Android 文件与文件夹访问](https://developer.android.com/training/data-storage/shared/documents-files)。

## 目录 JSON

兼容 PC 版的 `version: 1` 格式：

```json
{
  "version": 1,
  "mapping": { "offset": 10 },
  "bookmarks": [
    {
      "title": "第1章 基本概念",
      "page": 1,
      "children": [
        { "title": "1.1 定义", "page": 2 },
        { "title": "附录说明", "pdf_page": 20 }
      ]
    }
  ]
}
```

- `page` 是正整数印刷页码，`pdf_page` 是正整数 PDF 实际页码。每项必须且只能提供其中一个；封面是 PDF 实际第 1 页。
- `mapping.offset` 满足「PDF 实际页码 = 印刷页码 + offset」，允许正、零、负整数；省略 `mapping` 时偏移为 0。
- `children` 表达完整多级目录，数组顺序就是书签顺序。本版不再限制为 3–5 个一级条目。
- 分段映射可处理插页或缺页：

```json
"mapping": {
  "segments": [
    { "printed_start": 1, "printed_end": 100, "pdf_start": 11 },
    { "printed_start": 101, "printed_end": 200, "pdf_start": 113 }
  ]
}
```

区间包含两端，计算为 `pdf_start + page - printed_start`。`offset` 与 `segments` 二选一；区间不能重叠，目标不得越过真实 PDF 总页数，未被覆盖的印刷页会报错。

另兼容 Jasminum 原生 `{ "info": {...}, "outline": [...] }`：读取 `title`、物理页 `page` 与嵌套 `children`。导入前须核对页码从 1 开始；不自动给所有页码加 1。`x/y/collapsed` 等显示信息不决定书签目标。目录最大目标页不是 PDF 总页数，总页数始终由所选 PDF 读取。

无须 `schemaVersion`、文档标题或总页数字段。JSON 使用 UTF-8，可带 BOM；错误类型、重复字段、未知字段、空标题、空目录、越界页码或缺失映射会停止处理。仅支持上述格式，不把任意 JSON、TXT、Word 或 Excel 文件自动解释成目录。

## 原件与输出

生成在本地副本进行，结果通过目录、页数及原字节前缀检查后才允许保存。签名、加密、密码保护或无法安全处理的 PDF 会拒绝。

同名替换前将原 PDF 备份至应用内部持久目录 `files/pdf-backups/` 并同步。原文件夹中的新暂存 PDF 写入、同步且重读校验成功后，才将原件改为唯一备份名，再把新文件改为原名；每一步保存恢复记录，并核对真实名称、返回的新 URI 与文件内容。不会打开原件的截断写入流，也不自动删除同目录原件备份、暂存文件或应用内备份。两次改名之间可能暂时没有原文件名，因此仍需保留恢复记录，不能称为系统原子替换。

v0.1.8用一个清理按钮替代两个单独删除按钮，处理本次记录关联的外部旧件与应用内恢复备份。必须先核对正常使用、查看完整清单并确认不可恢复，才保存清理进度和执行；手动清理与生成/保存分开。删除前及过程中重查当前输出、旧件、内部副本、身份及SHA，先外部、后内部；中断后仍以原清单核验，未知变化停止。清理未结束时暂时禁止新写入，防止覆盖关联记录。不会按前缀扫描或猜测旧版关系。

v0.1.9仅改变享做目录全部替换模式：新目录核验成功后自动清理本次两份旧目录副本，PDF备份和保留并添加模式不自动清理。完全相同的目录树无需重写，也不删除以前任务的目录备份记录。自动清理前持久记录本次范围，显示完整两路径；失败明确区分“新目录已替换”与“旧目录清理未完成”，保留JSON、剩余材料和进度，可继续清理。也可将精确清单归档后选择保留剩余文件并结束清理，其他任务重新可用。自动删除成功后的旧目录不能恢复。

旧版v0.1.3–v0.1.7单独删除按钮保留应用内备份；新统一清理按用户明确选择也删除本次关联内部恢复备份，旧版丢失关联的内部文件保留。

清理前，中断或失败时可在第3节恢复原件并核验；重启发现未完成记录不会自动当成成功或删除 JSON。若旧版任务已使原 PDF 消失，使用「从备份恢复消失的 PDF…」，授权原文件夹后按保存的原名恢复；遇到同名的其他内容会停止，不覆盖。最近应用内备份也可另存导出。核对或导出前不要卸载应用、清除应用数据，以免丢失内部备份。读取可取消；改名切换和恢复期间需完成核验后才返回，避免打断恢复步骤。

系统杀进程、授权失效或文件来源故障时可能需要用户恢复。另存失败也可能留下未完成的输出文件。应用报告「PDF成功、JSON未删除」时，PDF已核验成功，JSON删除因权限/内容变化等停止。JSON 只在最终原名下的新 PDF 重读核验成功、恢复记录已处理后删除，不在暂存或改名中途删除。树授权及改名返回标识的规则见 [Android DocumentsContract](https://developer.android.com/reference/android/provider/DocumentsContract)。

## 源码与构建

源码入口为 `app/src/main`；显示版本只在 `VERSION` 更新，Gradle及界面自动同步，每次升级递增 `app/build.gradle` 的versionCode。使用 JDK 17、Android SDK Platform 35、Build Tools 36.0.0 和项目自带 Gradle 9.8.0 Wrapper：

```powershell
.\gradlew.bat assembleDebug lintDebug testDebugUnitTest --no-daemon --console=plain
```

也可用 `scripts/build.ps1 -ToolingRoot <含 jdk 和 sdk 的工具目录>`。标准构建输出在 `app/build/outputs/apk/debug/`。测试签名仅供本次安装验证；正式发布前需确认持续更新所用签名方式。

只读享做混合页码样本回归可添加 `-EnjoyMixedFixtureFolder '<含 catalog.json、pageids.json 和 doc 的样本目录>'`；当前案例对应实际 344 页样本。既有 434 页样本仍使用 `-EnjoyFixtureFolder` 配合对应 `-InputJson` 和 `-ActualPageCount`。两个参数也可传给 `scripts/release.ps1`；真实样本仅留本地，不进入公开源码包。

使用 `scripts/release.ps1 -OutputDirectory '<工程外的新版本交付目录>'` 依次完成构建、回归、签名/版本检查及打包；已存在的交付目录会被拒绝，避免覆盖历史版本。生成PDF_Bookmarks_v{版本}_android.apk、_android_source.zip及SHA256SUMS.txt；自动排除测试书籍、诊断资料与私钥。源码ZIP与APK一起保留，安装后的平板程序不依赖电脑上的测试缓存。
